# tipitaka.lk 的資料能不能當「全藏參照系」

> 2026-11-02 勘查 `D:\2023\tipitaka.lk\public\static`。
> 結論先講：**可以當「結構／義注」的參照系，不能當「逐句對齊」的來源**；
> 它補的正是 cs 最缺的一塊（義注的乾淨結構），但沒有複注（ṭīkā）。

## 1. 這是什麼

```
static/
  data/tree.json            16,355 個節點：全藏目錄（含義注），每筆 [巴利名, 僧伽羅名, level, [x,y], 父節點, 檔案]
  data/file-map.json        113 筆：節點 → 文字檔
  data/footnote-abbreviations*.json   腳注簡寫對照
  text/*.json               285 檔：巴利原文（僧伽羅字母），分頁、分段、帶標題層級
  text-apz/*.json           113 檔：僧伽羅語譯（同頁對齊，純字串，沒有結構）
  sitemap.txt               1.1 MB：網站地圖
```

`text/*.json` 的結構（實測）：

```json
{ "filename":"dn-1", "bookId":10, "pageOffset":0, "collection":"mula",
  "pages":[ { "pageNum":2,
              "pali":{ "entries":[ {"type":"centered","text":"…","level":4},
                                   {"type":"heading","text":"…","level":3},
                                   {"type":"paragraph","text":"1. evaṃ me sutaṃ …"},
                                   {"type":"gatha","text":"…"},
                                   {"type":"unindented","text":"…"} ] } } ] }
```

- `pageNum` 每次 +2：**一個 JSON 頁＝印刷本的兩面**，`pageNum` 就是印刷頁碼（BJT 版）。
- `paragraph` 的正文**開頭就是段號**（`1. `、`2. `…），而且**每經從 1 重編**。
- `centered` 裡單獨一個數字（`3.`）＝該經的經號；`heading`／`gatha`／`unindented` 是標題、偈、不縮排段。
- `text-apz` 是同一頁的僧伽羅語譯，`pages[].entries` 是純字串陣列（沒有 type）。

## 2. 收錄範圍（285 檔）

| collection | 檔數 | 內容 |
|---|---|---|
| `mula` | 177 | 全藏根本經：四部尼柯耶＋小部（khp…peṭakopadesa）＋阿毘達磨七論 |
| `atta` | 93 | **義注**：`atta-vp`(7)、`atta-dn`(5)、`atta-mn`(7)、`atta-sn`(6)、`atta-an`(13)、`atta-kn`(46)、`atta-ap`(9) |
| （無 collection） | 13 | `ap-pat`／`ap-yam` 的子檔（欄位缺漏） |
| `anya-vm` | 2 | 清淨道論（Visuddhimagga，276 頁） |

- **優點**：義注涵蓋到小部（46 檔），這是 cs 沒有的（cs 的小部義注只有零星幾本）。
- **缺點**：**沒有複注（ṭīkā）**。cs 有 `dn1t`／`mn1t`／`an1t`… 這批在 tipitaka.lk 找不到對應。
- 檔名是「書 + 頁段」：一本書會被切成數檔（`dn-1` 頁 2–148、`dn-1-3` 頁 150–322、
  `dn-1-6` 頁 324–482、`dn-1-11` 頁 484–642），**不是重複，是接續**。

## 3. 與 cs 的相似度（文字）

同一底本家族，但**不是逐字相同**：

| 測項 | 結果 |
|---|---|
| 開頭十餘詞 | 完全一樣（`evaṃ me sutaṃ ekaṃ samayaṃ bhagavā antarā ca rājagahaṃ …`） |
| 長部第 1、2、4 經的詞數 | cs 7,797／7,114／3,004 vs BJT 8,011／7,063／2,979（±3%） |
| 長部第 3、5、11、12 經的詞數 | BJT 是 cs 的 1.8／1.9／3.4／3.5 倍 |
| 全書字元數（dn1） | cs 333,504 vs BJT 445,404（+34%） |
| 省略號 `…` | cs 665 個、BJT **0 個** |

推論（證據充分但未逐句核對）：**CST（cs）用「…」壓縮重複段落，BJT 全部寫出來**。
所以兩邊在「有大量重複」的經（3、5、11、12）長度差最多，在沒有重複的經（1、2、4）幾乎一樣。

**這代表：不能拿行號或段號直接對應，要靠文字對齊，而且要先把「省略 vs 全寫」處理掉。**

## 4. 粒度（分句）

以四部 22 冊計（`mula`，不含小部與論）：

| | 數量 | 平均字數 |
|---|---|---|
| cs 句（adb 一行） | 118,019 | 95 |
| cs 段（`^n`，含範圍段號） | 6,554 | — |
| BJT 段落（`paragraph`） | 28,170 | 273 |
| BJT 偈（`gatha`） | 2,893 | — |

→ **一個 BJT 段落 ≈ 3–4 個 cs 句**（以字數 273/95≈2.9；以總數 118,019/28,170≈4.2）。
逐冊差異很大：dn1 約 2.2 句、sn1 約 6.8 句、an8 約 4.1 句。

→ BJT 段落比 cs 的「段」**細**（cs 的 `^n` 有 1,179 個範圍段號，一段可以蓋好幾段經文），
但比 cs 的「句」**粗**。它剛好卡在中間：**比句子粗、比 VRI 段落細**。

編號體系也不同：cs 的段號是**全冊連續**（dn1 是 1–559，跨經不重來），
BJT 是**每經從 1 重編**。所以 `pn` 不能直接對號。

## 5. 對兩條路的意義

| | 路一：factorization | 路二：全藏結構（含義注）參照系 |
|---|---|---|
| tipitaka.lk 能不能幫 | **幾乎不能**（不同語言、不同編輯體例，對拆詞沒有直接幫助） | **能，而且是目前看到最好的材料** |
| 具體用途 | — | ① 義注的乾淨結構（heading／段落／頁碼）② 義注的段落號 ③ 第五套頁碼（BJT）④ 僧伽羅語譯（頁級對齊） |
| 還缺什麼 | 需要 kmj 的拆分表與 `Formula` | 沒有 ṭīkā；要先做文字對齊（且處理「省略 vs 全寫」） |

## 6. 建議的下一步（小步、可驗收）

1. **先拿一本義注試對齊**：`atta-dn-1`（96 頁）對 cs 的 `dn1a`（320 段）。
   做法：把 BJT 段落轉成儉約巴利→IAST，對 cs 的義注正文做詞級對齊，
   量「BJT 段落邊界落在 cs 段內」的比例、以及能不能回填 cs 缺的塊 id（`dNaN`）。
   成功的話，cs 的 35 冊注疏就有救了——不必重編 id，直接用 BJT 的結構當骨架。
2. 頁碼：BJT 的 `pageNum` 可以當第五套頁碼（`b`）存進 adb（`<pb n="b123"/>`），
   對讀者「翻到紙本」有用；但**不要**拿它當定位（定位仍是 `ck.n`）。
3. 僧伽羅語譯（`text-apz`）是頁級對齊，可以先當「第十一個譯本」的候選，
   但要先確認授權與是否值得（它只到頁，不到句）。
