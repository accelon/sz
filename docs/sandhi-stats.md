> `context → sandhi 結果` 全部排出來，按出現頻次決定 codebook。
>
> 產生器：[`src/decomp/sandhi-stats.py`](../src/decomp/sandhi-stats.py)
> 資料：pwa 769,086 條有連字號拆解；下表是**全量**。

## 1. 方法與過濾

- 對每個 pwa 條目：`pre = parts.join('')`，用 difflib 對齊到 `surface`。
- 每個接縫 `b` 取左 L 字、右 R 字；結果 = 表面對應區間 `surface[map(b-L):map(b+R)]`。
- 只收完整窗口（`b>=L`、`b+R<=len(pre)`）；全部轉小寫。
- `identity` ＝結果等於 `left+right`，不列入 pattern；其餘按 `(left, right, result)` 計次。
- **長度過濾**：連音結果最多只比 context 多一個字，所以只收
  `1 <= len(result) <= L+R+1`。更長的是 pwa 拆分／對齊錯誤，直接丟掉。
  例：`a+a → asmima`（長度 6）就是這種；1+1 一共丟 4,067 個接縫（0.31%）。
- 表格的 `code` 就是頻次排名：**0 保留给 identity，1 是最高頻，依此類推**。

## 5. 幾個要注意的點

### 5.1 同一個 context 可以有多個結果

1+1 的 467 個 context 裡有 **327 個**有多個結果：

```text
aa → a   （code 2，45,371）
aa → ā   （code 3，40,758）
ai → ā   （code 4，19,067）
ai → an  （code 16，6,189）
ae → e   （code 6，13,461）
ae → ame （code 20，4,244）
```

這不是問題：**code 會區分結果**。decoder 看到 `code 2 + context aa` 就輸出 `a`，
看到 `code 3 + context aa` 就輸出 `ā`；encoder 依實際表面選 code。要取捨的是
pattern 表的大小，不是 context 的唯一性。

### 5.4 編碼長度

若 code 用十進位、0 是 identity：


平均每個有改寫的接縫只要 **1.59 個數字**；identity 接縫只要 1 個 `0`。
