# 提示詞：adb 定址升級為「多層地址」（向後相容、不重建 adb）

> 用法：開一個新話題在母工作區 `D:\2026\adb-converter`，把下面整段貼進去。
> 目的：讓 `rv.10.90.3`、`bu.2.4.5`、`sb.2.1.1.1` 這種多層地址可以直接跳，
> 舊的 `d1.7`／`a6.7:3` 行為完全不變，而且**不必重建任何 adb**。

## 給作者的三個提醒

1. **多層地址其實不需要動 adb**：`<塊 id>` 本來就是任意字串，`rv.10.90` 這種寫法現在就能存；
   卡住的只有閱讀器的解析規則。所以這次是純閱讀器升級，sz 的 8 顆、veda 的 4 顆都不用重打。
2. **真正會咬人的是歧義，不是多層**：`rv.10.90` 這種「像地址又像塊 id」的字串，
   用正規式永遠會猜錯；用「候選塊 id 是否存在」來決定切點才穩。這也是這次要改的重點。
3. **回歸比新功能重要**：sz 已經有 13 萬個地址在用，任何解析改動都要拿
   `addr-quick`／`addr-regress` 當門檻；新功能（多層）只是多一種合法輸入，不該改變舊輸入的結果。
