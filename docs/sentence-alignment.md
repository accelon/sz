> 目標（作者）：以 **dn／mn／sn／an** 為根，用 **sc 英譯、kmj 日譯、元亨寺 yh 漢譯**

## 1. 邊界：不動原本的人工對齊

- 句數相同的段：**保留原本 1:1**（作者花錢請人做的逐句對齊）。
- 只有「句數不同」的段才用詞錨重新對齊。這些段原本照行序沒有對應，是新補的。
- 全程只讀 `data/`，產物寫 `out/`；`data/` 的內容與行號不變。

## 3. 方法

1. **種子**：所有書裡「句數相同」的段，句 i ↔ 句 i 當作可信的句子對。
2. **詞對**：
   - 句子級共現 → Dice；互相最佳、每詞最多 2 個譯法；
   - `lex.adb` 的英文釋義（PTS）當先驗（有先驗時 Dice 門檻降為 0.2）；
   - 高頻詞用條件機率 `P(譯本詞 | Pali 詞) ≥ 0.5` 補；
   - Pali 詞做粗糙詞幹化（去格尾），減少詞形分裂。
3. **段內句對齊**：DP，允許 1:1／1:2／1:3／2:1／3:1；分數是 F1
   （Pali 詞被譯本覆蓋 × 譯本詞被 Pali 解釋），合併有罰分、空位有小罰分。
4. **EM**：第一輪對齊後，只收「1:1 且分數 ≥0.45」的句對，重新學詞對再對一次。
5. **空位歸併**：沒有詞錨的句子併進相鄰的有錨組，分數記 0（低信心，待人工核）。

## 6. 限制與下一步

- 高信心比例仍低（英文 20–39%）：詞對精度受「同句多詞互相干擾」影響。
- 空位歸併的 0 分句對「有位置、不可靠」，只能當待人工核。
- 英文漏 `nibbāna`／`anattā` 是譯法不同（Nibbāna、not-self），需同義詞表。
- 下一步：①句內位置特徵；②把高信心句對回饋第三次 EM；③用這套對齊做**漏譯偵測**
  （Pali 句有實詞、對應譯本句為空或 0 分）。

### 走過的死路（都已回退，記下來免得後人重走）

1. **單調對角先驗**（1:1 時 `+0.04×(1−|i/n−j/m|)`）：覆蓋變差（dn1 85%→75%、sn1 94%→62%）。
2. **DP 參數掃描**（MERGE 0–0.1、GAP −0.01–−0.05）：覆蓋 84–86%、高信心都停在 24%，
   差異在誤差內 → 瓶頸不在參數，在詞庫。
3. **用 SC bilara segment key 直接對映英語**：SC API 與 GitHub 的 bilara root 都可用、key 也共用，
   但 bilara dn1 root 只有 7,808 詞，我們的 `data/sc/dn1` 有 45,274 詞——**bilara 是節略版**，
   對不到全文，路線暫停。

### 下一步（優先序）

1. 詞庫：把 `lex.adb` 的中文釋義與 PTS 英文釋義做「譯法同義詞」對照（`Nibbāna`／not-self 這類），
   再把高信心句對回饋成第三次 EM。
2. 有了可靠的英語對齊後，回頭校正漢譯／日譯，並開始**漏譯偵測**（Pali 句有實詞、對應譯文為空或 0 分）。
3. 細分：如果要做「一句拆多句」，用這裡的詞對當錨點，先提案、不自動改。
