# 設計理念與洞察紀錄（2026-11-03）

> 這一頁記「**為什麼**這樣做」：作者在這幾輪對話給的判斷，加上量測後被證實或修正的部分。
> 規格在 [`addressing.md`](addressing.md)，斷句問題在 [`segmentation.md`](segmentation.md)；
> 這裡只記原則、理由與已經量到的數字。日後動工前先讀這一頁。

## 1. 為什麼先把「句」做好

- **作者**：在自己接觸 AI 之前，就已經決定一定要先做好**句粒度對齊**，「將來一定用得上」。
  為此花了十幾萬台幣請人做人工**逐句對齊**。
- 這也是整個工作區最貴、最難重建的資產：文字可以再換（CST→deva→IAST），
  但人工判斷的「哪一句對哪一句」換不回來。
- 所以任何改動的第一原則是：**不能動到段／句的位置**。

## 2. 基礎是「段／句所在的那一行」

- **作者**：最關鍵是 `<區>`、`<段>` **所在行的位置**——那是定位的基準，
  有時也是閱讀的單元（讀窗）。
- 我們的做法：換文字時只換行裡的字母，**不動行、不動任何標記**。
  結果：段號→行號 220/220 檔完全一致（359,662 段），人工對齊的座標原封不動。
- 推論：只要「段＋行」不變，外部（頁碼、異文、別人的引用）全部照舊。

## 3. 抓大放小

- **作者**：不要抓住小 bug 不放；先把**高質量的句定位**產生出來，其他問題留給後人慢慢解決；
  **句定位標準化，協作就會變得非常容易**。
- 落實：
  - 先定規格（`塊.段:句`，句＝段內第 j 個**有文字的行**，空行不算）。
  - 先做量測（段是否唯一、句序是否連續、空行是否被排除），把瑕疵列成清單，不逐條去修。
  - 先給工具（`src/addr-resolve.ts`），讓別人不必重實作。

## 4. 寧細勿粗

- **作者**：句子可以多給幾個號，「合起來很容易」；但未來若要在 `1` 和 `2` 之間**插號**，
  麻煩得多。所以能不切就不切的想法是錯的，**能切就切**。
- 落實方針：
  - 現在就切（還沒有人依賴 `:句` 的時候）。
  - 切句只影響同段之後的行號，段的位置不動；合併則是刪行，也容易。
  - 切句的來源優先序：明確句末（`।`／`॥`）→ 子句邊界（`–`／`;`）→ 平行譯本的斷句。

## 5. SuttaCentral 的設計問題（我們不要重複）

作者以 SC 為斷句基礎，但明確指出它不夠好：

1. **只依標點切**：沒有標點的段落會變成一長串，SC 沒有再處理。
2. **同一定型句有時斷、有時不斷**：同一個公式在 A 經自成一句、在 B 經黏在上一句，
   對齊時會誤判成漏譯／衍文。
3. **JSON 一句一個 key**：要加句子就得重排 key、改所有引用，成本高，所以他們不太動。

我們的優勢：

- adb 的「句」是**行序隱含**的，不是資料裡的 id；切句＝多一行，**沒有 key 要維護**。
- 所以我們可以「寧細勿粗」，而 SC 的格式反而鼓勵「少切」。

## 6. 「句不保證同號」是無奈，不是設計

- **作者**：跨譯本句數不一致，是因為**人工錯誤與漏譯**，不是對齊沒做。
- 我們的解讀：段內句數不同，至少有四種原因——**合併、標記、漏譯、錯位**；
  只看行數分不清，必須有詞庫才能在段內做詞錨定的句對齊。

## 7. 詞庫是下一步的鑰匙

- 作者：把詞庫做好，就能自動找出這些問題，進一步把句子對齊、甚至再細拆分。
- 第一版已抽出 `out/lexicon.tsv`：74,219 條（72,709 條有中文釋義、48,244 條有詞件），
  覆蓋 cs 的 `<詞>` 出現次數 **82.3%**；缺的是長複合詞，可用詞件遞迴拆。
- 下一步（pilot 已跑）：ccc 的 dn1／mn1／an1 做段內句對齊，先分開「合併／標記／漏譯／錯位」。

## 8. 勘誤與上游

- **作者**：勘誤表是用 **SuttaCentral 對勘**過的，多半是 **CST 的輸入錯誤**（不是版本異讀）。
  官方 deva master 改好的就從本地移走（`data/cs-index/errata-retired.tsv`）。
- 資料源改用 **accelon/tipitaka-xml**（VipassanaTech 的 fork）；**有改動就發 PR 給上游**
  （流程見 `src/pr-deva.ts`；第一批 #2740）。

## 9. 留給後人的（不擋路）

- `cs` 的 `an3t` 有 24 個重複段（位址撞號）。
- 部分譯本有「0 句的段」（yh 78、xsq 46、pku 23、kmj 19、cs-mm 3）。
- 閱讀器 `anchorVa()` 仍用行數推算（空行會多算）；母區 `page-text.ts` 要改成同一規則。
- 定型句要不要統一成「自成一行」、長句要不要再切，屬斷句決策，見 `segmentation.md` §4。
